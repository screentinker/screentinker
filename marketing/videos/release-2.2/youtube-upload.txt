---------------------------- DESCRIPTION -------------------------------

ScreenTinker 2.2 serves a Model Context Protocol endpoint, so you can point
Claude - or anything else that speaks MCP - at your own signage server and ask
for things in plain English. "Which screens are offline?" "Put the autumn
campaign on the lobby screen." We don't know of another digital signage
platform that does this.

It is a client of your own public API, not a second way into the database:
every tool call is an HTTP request carrying your token, through the same
workspace isolation and the same rate limits a script would hit. The tool list
is filtered by that token's scope - a read-only token is shown ten tools, a
full one twenty-one, and the read-only one is never even told the write tools
exist.

ScreenTinker is open source. Host it yourself, or let us run it for you.

In this video:
- MCP: 21 tools, chosen rather than generated, filtered by your token's scope.
- Tokens are issued by a person, not by the assistant - and the auth guide says so.
- Every published page has a Markdown version, plus an RFC 9727 API catalogue.
- Device REST and the LAN control door: API only for now, and the video says so.
- E-paper and ESP32 signs: dithered, packed and deep-slept by the server.
- Eleven platforms, each with a guide, and a downloads page built from what
  your instance actually has.
- Apple TV documented as NOT supported, with the reasoning.
- Also fixed: Esc on the web player now wants the screen's settings PIN, the
  dashboard notices its own updates, and reports stopped returning nothing for
  valid date ranges.

Every screen in this video is a real ScreenTinker instance with invented demo
data. The MCP exchanges are real: the questions were asked against that server
and the answers are what it returned.
