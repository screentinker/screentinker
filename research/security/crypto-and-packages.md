# Templates library: crypto, packages, catalog trust, zip, store, CLI (adversarial review)

Date: 2026-09-29. Scope: `server/lib/templates/{package,signing,params,catalog,store,zip,render,widget}.js`,
`scripts/template-catalog.js`, and the `/api/templates` import path. Worktree `st-templates-research`, Node 20.20.1.
No core code was modified.

**Tests:** `server/test/templates-security-crypto.test.js` (45 tests). Run with
`export PATH="$HOME/.nvm/versions/node/v20.20.1/bin:$PATH"; cd server && node --test test/templates-security-crypto.test.js`.
Every test asserts the **safe** behaviour. `[BUG-xx]` tests fail until the fix below lands, and
`[SAFE]` tests pin attacks that held. Current result: **27 pass, 18 fail (14 distinct bugs)**. The existing `templates.test.js` still passes 29/29.
All keys are generated per run. The real catalog key was not used or read.

## Findings

| ID | Attack → result | Severity | Exact repro | Proposed fix |
|---|---|---|---|---|
| **BUG-01a** | **Quadratic ReDoS in the CSS `url()` rewrite.** `/url\(\s*(['"]?)([^'")]+)\1\s*\)/g` makes every `url(` start position scan to the end of the string when there is no `)`. Measured: 64 KB = 1.3 s, 100 KB = 2.8 s, 200 KB = 13 s, so a 1 MB file (the per-file cap) blocks the event loop for about 5 min. It runs on the **entry HTML too**, not only on `.css`, and on **every render**: `GET /api/widgets/:id/render` and previews have no render cache. | **High** (whole-server DoS from one installed html template; the reviewer sees a CSS file of junk) | test `[BUG-01a]`: html package with `s.css` = `'url('.repeat(16384)`, then `render.buildHtmlDocument(env,{},{})` takes > 1 s. | Exclude `(` and whitespace from the unquoted branch so each start stops at the next `url(`, and bound the quoted branches: `/url\(\s*(?:"([^"\n]{0,2048})"\|'([^'\n]{0,2048})'\|([^'"()\s]{1,2048}))\s*\)/g`. Also rewrite each CSS file once per render (memoise), not once per reference. |
| **BUG-01b** | **Render memory amplification crashes the process.** Each `src/href/poster/url()` reference base64-encodes the target file again, and `MAX_DOC_BYTES` is checked only **after** the full string is built. Measured: 300 refs to a 1 MB PNG (5 KB of HTML) adds **1.2 GB RSS**. 5,000 refs (85 KB) adds **5.8 GB** and then throws `RangeError: Invalid string length`, which `renderTemplateWidget` does not catch. 20,000 refs (340 KB) makes **Node abort with a fatal OOM**, and because players re-fetch, the server crash-loops. | **High** | test `[BUG-01b]`: 200 × `<img src="a.png">` + 900 KB `a.png` produces **246 MB** of base64 for a 3.4 KB HTML file. Crash repro (run under `ulimit -v 8000000`!): `'<img src="a.png">'.repeat(20000)` + 1 MB PNG, then `buildHtmlDocument` exits with code 134. | (1) Memoise `inlineFile(p)` per render. (2) Keep a running byte budget inside the replace callbacks and abort (throw a sentinel → `blankPage`) as soon as it exceeds `MAX_DOC_BYTES`. (3) At install (`checkInstallable`), do a dry-run render with default values and refuse > `MAX_DOC_BYTES`. (4) Wrap `renderTemplateWidget` in try/catch → `blankPage`. (5) Optionally cache the rendered document by `(sha256, values hash)`. |
| **BUG-02** | **Small-order Ed25519 public key = universal forgery.** Node/OpenSSL accept the identity point `01 00…00` as an Ed25519 public key. With it, the signature `R = identity, S = 0` (`01 00…00` followed by 32 zero bytes) verifies for **every** message. `addCatalog` (and `TEMPLATE_CATALOG_PUBLIC_KEY`) accept such a key, so **anyone**, not only the key holder, can sign packages and indexes for that catalog. Confirmed: a forged html package imports as `trust: verified`. | **Medium** (needs an admin to add the key, for example from a malicious or careless catalog operator. After that, forgery is open to the whole internet, and "catalog operator is honest" no longer suffices.) | tests `[BUG-02]` ×2: `addCatalog({publicKey: rawKeyToPem(01 00…00)})` succeeds, then `importPackage(envelope with sig=01 00…00 ‖ 00×32)` gives `verified`. | In `signing.toPublicKey`, reject the libsodium `has_small_order` blocklist, comparing with the sign bit masked (`raw[31] & 0x7f`): y = `00…00`, `01 00…00`, `ec ff…ff 7f` (p−1), `ed ff…ff 7f` (p), `ee ff…ff 7f` (p+1), `26e8958fc2b227b045c3f489f2ef98f0d5dfac05d3c63339b13802886d53fc05`, `c7176a703d4dd84fba3c0b760d10670f2a2053fa2c39ccc64ec7fd7792ac037a`. Every key path (official, env, `addCatalog`, stored rows) goes through `toPublicKey`. |
| **BUG-03** | **Disabling a catalog does not distrust its installs.** After `setCatalogEnabled('community', false)`, the same signed file re-imports as unsigned and is refused as html code, but the **existing** install stays `trust: verified` and `usable()` returns `null`, so its code keeps running on screens. Key rotation of the official key (`ensureOfficial`) behaves the same way: installs signed by the old key stay verified. This is the incident-response path ("key compromised, turn it off") and it does nothing to deployed code. | **Medium** | test `[BUG-03]`. | Record `signer_key_id` in `templates_installed`. In `usable()`, a `verified` row counts as verified only while its catalog exists, is enabled, and its current `keyId` equals the recorded one. Otherwise treat it as `unverified`, so html is gated by `templates_allow_unsigned_code`. Bump the catalog's widgets when it is toggled. |
| **BUG-04** | **Revocations fail open.** `validateIndex` silently filters malformed revocation data. `versions: ["v1.0.0"]` or `["1.0.*"]` becomes `[]` and matches nothing. `id: "Lobby-Welcome"` becomes `id: null` and matches nothing. Upper-case sha256 values are dropped. `cmdBuild` copies `revoked.json` into the index **without validating it**. A maintainer typo in an emergency revocation revokes nothing, and nothing reports it. | **Medium** | test `[BUG-04]`: signed index with `revoked:[{id:'lobby-welcome',versions:['v1.0.0']}]`, then `acceptIndex` succeeds and the install stays `active`. | Fail closed. In `validateIndex`, **refuse the index** (CatalogError) if any revoked entry has an invalid id, a non-array or empty-after-filter `versions` without a valid `sha256`, or an invalid sha. As a fallback, invalid versions → `['*']`. In `cmdBuild`, validate `revoked.json` with the same function and `die()` on error. |
| **BUG-05** | **The index entry that a consent UI shows is never checked against the package.** `library()` returns the **index's** `kind` and `network`. `installFromCatalog` checks only sha, id and version. A signed index saying "slide, no network" for an html package that talks to `api.example.com` installs without complaint. `sign` (BUG-05b) does not compare them either, so a tampered CI `dist/index.json` with consistent hashes but edited metadata gets signed. | **Medium** | tests `[BUG-05]` (server) and `[BUG-05b]` (CLI: edit `dist/index.json` `kind`/`network`, then `sign` exits 0). | In `installFromCatalog` (and the signed-import path when the version is listed), refuse unless `manifest.kind === t.kind`, `sorted(manifest.network) == sorted(v.network)`, and `manifest.min_server === v.min_server`. In `cmdSign`, run the same cross-check (plus name) before signing. Better still, `sign` regenerates these index fields from the manifests instead of trusting them. |
| **BUG-06** | **Canonical check compares strings, not bytes.** `parsePackageBytes` compares `canonicalJson(obj)` with `bytes.toString('utf8')`. Invalid UTF-8 (for example `0xFF` in place of the `EF BF BD` of a U+FFFD in `description`) decodes to the same string, so it passes, but it has a different sha256. That breaks the spec's "one package, one encoding, one hash". Practical impact is small: signatures and index pins cover raw bytes, and unsigned content can always be varied. | **Low** | test `[BUG-06]`. | `if (!Buffer.from(canonicalJson(obj), 'utf8').equals(bytes)) fail('package bytes are not canonical')`, and decode with `new TextDecoder('utf-8', { fatal: true })`. |
| **BUG-07** | **`B64_RE` overflows V8's regexp stack** at about 4.47 M characters (3.35 MB decoded), throwing `RangeError: Maximum call stack size exceeded`. A valid package cannot get that big, but an 8 MB upload (the envelope cap) hits it, and the raw V8 message becomes the API error. It fails closed. | **Low** | test `[BUG-07]`: `parseEnvelope({format, package:'A'.repeat(7.5e6)})` throws a RangeError, not a PackageError. | Check the length first (`s.length > Math.ceil(MAX_ENVELOPE_BYTES/3)*4` → fail), then validate with non-backtracking checks: `s.length % 4 === 0`, `!/[^A-Za-z0-9+/=]/.test(s)`, and `=` only in the last 2 positions. | **BUG-08** | **Zip memory amplification.** `readZip` bounds the total by the **claimed** sizes but caps each real inflate only at `maxFileBytes`. Offline bundle caps are 4000 entries × 8 MB, with a total of 512 MB. Measured: a **498 KB** archive whose central directory claims 0 bytes for 60 × 8 MB zero entries puts **503 MB** in RAM in 0.7 s. | **BUG-09** | **A signed import ignores other catalogs' sha256 revocations.** The unsigned path checks every catalog's index, but the signed path checks only the signer's catalog. On an air-gapped server a reinstall then fails ("the community library is switched off…"), and the admin has to re-import the bundle. | Low / functional | test `[BUG-10]`. | Before unlinking, also check whether any enabled catalog's cached index pins that sha, or track bundle-cached files separately. |

### Informational (no failing test)

- **I-1. Cross-catalog sha revocation is permanent and unscoped.** Any enabled catalog can black out any install from any catalog by listing its sha256 (documented as intended). Such a revocation is **never lifted**, because the lift needs `row.catalog === revokingCatalog`. Consider recording `revoked_by` in its own column and scoping foreign-catalog sha revocations to `local` rows only.
- **I-2. Serial reset by remove + re-add.** `removeCatalog` then `addCatalog` resets `last_serial` to 0, so an old signed index is accepted again. `ensureOfficial` on key change does the same. Both are admin actions. Consider keeping a per-key_id high-water mark.
- **I-3. Signed but unlisted versions import as verified.** An old signed version that was dropped from the index (not revoked) imports as `verified`, which is a downgrade path. Consider refusing a signed version older than the newest listed one unless the index lists it.
- **I-4. Signer-controlled index oddities.** A serial of `2^53−1` would freeze a catalog forever. `expires` accepts non-strings through `Date.parse` coercion (`["2099-01-01"]`). The last base64 character of `index.json.sig` has 4 ignored bits, so 16 texts give the same signature. All harmless because the index is signed. Tightening them is cheap.
- **I-5. Gaps in the display-string filter.** `str()` refuses C0, DEL, U+200B–200F, U+202A–202E and U+2066–2069, but allows C1 controls (U+0080–009F), U+061C, U+2028/2029 and U+FEFF. The index `s()` does not strip U+200B–200F. This is a minor spoofing surface.
- **I-6. Extra keys in the envelope `signature` object.** Extra keys are accepted and ignored, and `installFromCatalog` stores the downloaded envelope verbatim. Harmless; strict key checks would match the rest of the parser.
- **I-7. `__proto__` zip entry replaces the prototype of `readZip`'s result object.** There is no global pollution (tested), but use `Object.create(null)` or a `Map`.
- **I-8. `putPackageFile` durability.** It neither fsyncs nor removes the tmp file on failure. It fails closed: `loadPackage` refuses a torn file.
- **I-9. Deep nesting.** 200k-deep arrays in the manifest make `canonicalJson` throw a RangeError, not a PackageError. The import path converts it to a CatalogError (400) within milliseconds, so it is safe, just unlabelled.

## Verified safe (attacked, held)

- **Ed25519:** S + L (non-canonical scalar), all-zero and all-FF signatures are rejected by Node 20's verify. Signatures over the envelope, over a sibling package with the same id/version, raw no-context signatures, and cross-domain signatures (index ↔ package) do not verify. A key_id that is upper-case, too long, too short, binary or non-hex is refused at parse. A key_id collision is irrelevant, because every candidate key is actually verified.
- **A disabled catalog's key** is not trusted for new imports (they become `local/unverified`), and its index is refused.
- **Base64:** whitespace, the URL-safe alphabet, missing or extra padding, non-canonical tail bits (`QR==`) and interior padding are all refused.
- **Canonical JSON:** the spellings `-0`, `1.0`, `1e0` and `\u004c`, `\/`, duplicate keys, a BOM, a trailing newline, `1e400` and non-finite numbers are all refused as second encodings.
- **Prototype pollution:** `__proto__` in the manifest or files is refused. A `__proto__` in values or in the template.json document is skipped by `substitute`. The legal param name `constructor` stays an own, validated value. `Object.prototype` is untouched (also for zip entry names).
- **ReDoS (all < 100 ms on 1 MB pathological input):** `HOST_RE` (many labels, hyphen labels, long label), `resolveRef`, the src/href/poster rewrite (unterminated, whitespace runs, mixed quotes), the doctype strip, and `strictBase64` with a junk tail. `PATH_RE`, TZ, locale and homepage are bounded or linear. The only offender is BUG-01a.
- **Serial:** 1.5, `"5"`, `2^53`, `2^53+2`, `1e300`, 0, negative, null and true are all refused. An equal serial with identical content is accepted as a re-fetch. An equal serial with different content, a lower serial, and a lower serial via an offline bundle are all refused. A revocation cannot be lifted by an older or equal-serial index, by re-importing the revoked file, or by a foreign catalog's index.
- **Index signature file:** another key, a package-domain signature, junk, spacing, upper-case and a doubled signature are all refused. A trailing CRLF is accepted.
- **`resolveUrl`:** `\\evil\x`, `\t//evil`, `\n//evil`, `%2e%2e` in every case mix, `.%2e`, `%2e.`, `HTTPS://`, `/\evil`, `https:evil`, `@evil` and fullwidth dots all stay on the catalog origin under its base path. `validateIndex` already drops absolute URLs, a leading `/`, `..` and anything over 300 characters. The only escape is BUG-12, which needs a misconfigured base.
- **Zip** (hostile names are written into the raw bytes, because archiver sanitises them): `../x`, `a/../../x`, `/abs`, `C:/x`, depth greater than 6, NUL/C0, backslash traversal, `./x` versus `x`, case duplicates, `a//b` versus `a/b`, `a\b` versus `a/b`, and the same name twice in the central directory are all refused. Symlink entries, the encrypted flag and unsupported methods are refused. A stored/deflate disagreement between the central directory and the local header never exceeds the cap. A truncated archive is refused. A claimed-small entry inflating past the per-file cap is refused (BUG-08 is the under-the-cap variant).
- **Offline bundle:** stray files, a case-variant package path, the pinned path present twice, `packages/../index.json`, a bundle for an unknown catalog, and a pinned path whose bytes do not hash to the pin are all refused or dropped. 4000 entries import in about 250 ms, and 4001 are refused.
- **Store:** `packagePath` accepts only 64 lower-case hex characters (traversal, upper-case, 63/65 characters, a suffix and NUL are refused). A package swapped on disk means the cached **verified** copy keeps serving and a cold load refuses the swap. No `.tmp` files are left behind. Uninstalling one catalog key keeps a file that another install still references.
- **CLI:** `sign` refuses a package whose bytes differ from the index sha, and a package of another id placed at the listed URL. `build` refuses symlinks, including a symlinked `manifest.json`, and refuses re-publishing a version with new bytes against `--previous`. A tampered previous package carried over by `build --previous` is then refused by `sign`. `verify` fails when package bytes are swapped (even re-signed by another key) and when index bytes are touched.
- **Sizing:** an 8 MB envelope is rejected in under 100 ms. It fails closed, although with the wrong error type (BUG-07). A 2 MB adversarial index built to maximise revocation scanning (14k revoked shas, 6.5k versions) gives `acceptIndex` in 36 ms and `library()` in 174 ms.

## Suggested fix order

1. BUG-01a and BUG-01b. Either lets one installed template take down the whole server. Also wrap render in try/catch.
2. BUG-03, BUG-04 and BUG-05/05b. The kill switch, the revocation list and the consent data must fail closed.
3. BUG-02, a small blocklist in `toPublicKey`.
4. D-1, a `sign --source --previous` workflow before the first real catalog release.
5. The remaining Low and functional items.
