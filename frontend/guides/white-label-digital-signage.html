White-label your ScreenTinker dashboard and player

Customize the look of your ScreenTinker dashboard and player for your clients. Add your brand name, logo, colors, and custom domain to make the system appear as part of your own organization.

This guide covers how to set up white-label branding for your workspace, the platform default branding that applies when workspaces don't have their own settings, and how to configure a custom domain. It also explains what white-labeling does and doesn't cover, including email branding, installed apps, and how to set up DNS.

Before you start

  • You need an Enterprise plan. White-label branding is only available on the Enterprise plan. Non-enterprise users will see an upsell box with a link to View Plans.
  • White-label settings are in Advanced view. New accounts start in Simple view. Switch with the Simple / Advanced buttons at the top of the menu.
  • You need workspace admin permissions. Only users with workspace admin rights can save branding settings for a workspace.

Access White Label settings

In Advanced view, choose Settings in the sidebar. Scroll down to the White Label / Branding section. This is only visible for Enterprise users or platform administrators.

Enterprise plan required

White-label branding is only available on the Enterprise plan. If you're not seeing this section, check your plan or contact support@screentinker.com to upgrade.

Set workspace branding

Workspace branding customizes the appearance of your dashboard and player for this specific workspace. Enter the following details:

  1. Brand Name: The name to display in the dashboard (e.g., "My Company Signage"). If you set this, it replaces "ScreenTinker" in various UI strings.
  2. Logo URL: Enter a public URL for your company logo. Must be HTTPS and publicly accessible. Logo is shown in the sidebar and player.
  3. Primary Color: The main accent color used in the dashboard UI. Choose from the color picker or enter a hex code (e.g., #3B82F6).
  4. Background Color: The background color of the dashboard. Choose from the color picker or enter a hex code (e.g., #111827).
  5. Favicon URL: Enter a public URL for your favicon image (e.g., a 16x16 or 32x32 PNG). Must be HTTPS and publicly accessible.
  6. Custom CSS (optional): Add custom CSS to further style the dashboard. This is applied only to the workspace's dashboard, not the player.
  7. Hide platform branding: When checked, hides the "Powered by ScreenTinker" branding in the dashboard and player.

Custom domain and CSS are platform admin only

The Custom Domain and Custom CSS fields are only available to platform administrators. Other users will see these fields as read-only with a tooltip "Only a platform administrator can change this".

On a self-hosted server

For self-hosted servers, the platform default branding is visible in the Platform area under Settings → Branding. Platform administrators can set default branding that all workspaces inherit unless they have their own workspace settings.

Apply branding to dashboard and player

Once saved, your branding will appear on:

  • Dashboard: The sidebar logo, accent color, and branding text
  • Login page: Your brand logo and colors
  • Player: Custom brand name in setup screens
  • APK download: APK file name will use your brand name

Set up a custom domain

With a custom domain, your dashboard will appear under your own URL. Custom domains are platform-admin only and require DNS configuration:

  1. DNS setup: Create a CNAME or A record that points your chosen domain (e.g., signage.yourcompany.com) to your ScreenTinker server's IP address.
  2. Reverse proxy: Set up a reverse proxy with TLS that forwards requests to your ScreenTinker server. The proxy must pass the Host header so hostname matching works correctly.
  3. Platform admin configuration: In Platform → Branding, enter your custom domain in the Custom Domain field and save.
Custom domain requirements

Custom domains require:

  • A public DNS entry (CNAME or A record) pointing to your server
  • A reverse proxy with TLS configured
  • The platform administrator to enter the domain in Settings

What white-labeling does not cover

White-label branding customizes the dashboard and player appearance, but does not change these elements:

  • Emails: Email subjects are hardcoded as "[ScreenTinker] <subject>" and sender names fall back to config.graphSenderName or "ScreenTinker". Workspace branding is NOT applied to emails.
  • Installed apps: Android/Fire TV, Tizen, webOS, Roku, iOS/tvOS, and native players keep their own names/icons. Branded app builds require a custom white-label agreement with support@screentinker.com.
  • Brand kit for signs: The "Your brand" feature in the Make a sign section is separate from white-labeling.
Important gotchas

  • Logo and favicon URLs must be publicly accessible HTTPS URLs
  • Once a workspace saves branding, it overrides the platform default completely
  • When "Hide platform branding" is checked and no custom name is set, the player shows no name at all
  • Custom domains require DNS setup and reverse proxy configuration (not handled by ScreenTinker)

FAQ

Can I use white-labeling with a self-hosted server?

Yes. Self-hosted customers can set up workspace branding and platform default branding just like hosted instances, but they must also configure DNS and reverse proxy for custom domains.

What happens if I don't enter a brand name?

If you don't enter a brand name, the player setup screen will still show "ScreenTinker" as the product name. The dashboard will still use the default branding unless a workspace or platform default sets a custom name.

Are emails affected by white-labeling?

No. Email subject lines and sender names are hardcoded and not affected by workspace branding settings.

Can I customize the player layout with white-labeling?

White-labeling only affects visual elements like colors, logos, and names. It doesn't change player layouts or transitions — those are handled separately in the player configuration.
