MagicINFO Is Being Retired: Keep Your Samsung Screens, Change the Software

Samsung is ending MagicINFO. If you run Samsung signage displays on it, you do not need new screens. Here is what is changing, how to move a Samsung display to ScreenTinker in its own menu, and what comes across from MagicINFO.

What Samsung is changing, and when

  • MagicINFO On-Premise: End of Sale on 31 December 2026, End of Support on 31 December 2029.
  • MagicINFO Cloud: End of Service on 28 February 2027.
  • The successor is Samsung VXT, Samsung's cloud-based CMS.

Dates from Samsung's VX documentation, read November 2026. Check it for changes before you plan around them.

The short answer

VXT is the path Samsung offers, and it keeps you on Samsung's own software for Samsung screens.

ScreenTinker is open source (MIT licensed) and runs on the same Samsung displays, plus LG webOS, Android TV, Fire TV, Roku, Raspberry Pi, Windows and any browser. You can run it on your own server, which matters if you chose MagicINFO On-Premise to keep your signage off a vendor cloud, or use the hosted version.

Move a Samsung display to ScreenTinker

Nothing has to be installed on the screen. The display's built-in URL Launcher opens the ScreenTinker player.

  1. Create a ScreenTinker account, or set up your own server.
  2. On the display, open the menu and go to System > Play Via and choose URL Launcher (called Custom App on Tizen 6.5 and later).
  3. Set the URL to https://screentinker.com/player, or your own server's address followed by /player.
  4. Make URL Launcher the source the display boots into (Settings > System > Auto Source Switching, or the URL Launcher Settings entry, depending on firmware).
  5. Pair the screen with the code it shows, then assign a playlist.

The Samsung TV and SSSP guide has the details, including which model years work and what to do if a screen stays on its setup page.

What comes across from MagicINFO

ScreenTinker can import from Xibo, Yodeck, ScreenCloud, Screenly and Anthias through their APIs. MagicINFO is different: its server API lists content and playlists, but Samsung documents no way to download the files themselves, and an import without the files would leave every playlist empty. So, for now:

  • Images and videos: copy them out of MagicINFO (on an On-Premise server, uploaded files are kept in the server's runtime folder) or use your original files.
  • Playlists: put the files in a zip with one folder per playlist, or add a playlists.csv, and use Switch to ScreenTinker, the import wizard in the dashboard. Each folder becomes a playlist of its files, in name order.
  • Rebuild, do not import: MagicINFO Author layouts, video wall layouts, tickers and data links. ScreenTinker has its own layouts and zones, video walls and widgets.

A direct MagicINFO import may follow once it can be tested against real MagicINFO servers. If you have one you can help test with, tell us on Discord.

Running MagicINFO 9 On-Premise? Patch it while you move

Two MagicINFO 9 Server vulnerabilities have been exploited in the wild: CVE-2024-7399 and CVE-2025-4632. If your server is reachable from the internet, update it or take it off the internet until it is retired.
