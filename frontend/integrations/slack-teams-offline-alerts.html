Screen offline alerts in Slack, Microsoft Teams and PagerDuty

A blank screen in a lobby or a store window costs you until someone notices. Alert channels tell the right team as soon as a screen has been offline for the minutes you choose, and again when it comes back, in the tools they already watch.

This is about the health of your screens. It sends messages about screens to Slack, Teams and others. It does not put Slack or Teams content on a screen.

How it works

  • Channels. Slack and Microsoft Teams (through an incoming webhook), PagerDuty (Events API v2), email (up to 20 addresses) or any webhook.
  • When to alert. Each channel says how long a screen must be offline first (2 to 1440 minutes, 5 by default) and whether to send “back online” too.
  • Which screens. All screens in the workspace, some groups, or some screens. Send the warehouse to one channel and the lobby to another.
  • No noise. One message per outage per channel, and “back online” only after an offline alert went out.
  • PagerDuty closes itself. The incident opens when the screen goes dark and resolves when it comes back.
  • Signed webhooks. A generic webhook gets a JSON body, signed with your shared secret in X-ScreenTinker-Signature when you set one.

Set it up

  1. Get an address from the other side. For Slack, create an incoming webhook (it is on hooks.slack.com). For Teams, create a Workflows incoming webhook for the channel. For PagerDuty, copy an Events API v2 routing key from a service.
  2. Add a channel. A workspace admin opens Automate → Alerts, adds a channel of that kind and pastes the address, key or email list.
  3. Choose the rules: minutes offline before alerting, whether to send back-online messages, and which screens.
  4. Press Send test. The message arrives in the channel, or the error is shown on the channel.

Security

A Slack or Teams webhook address lets anyone who holds it post into that channel, and a PagerDuty key opens incidents, so ScreenTinker treats them as credentials. They are never shown again after saving and never logged. Every address is called through the server’s network guard: public https addresses only, with no redirects followed. Only workspace admins can add or change channels.

Limits

  • Alerts cover screens going offline and coming back. Other events, such as an emergency alert or a published playlist, are available as Zapier and webhook triggers.
  • A failed delivery is retried, up to three attempts, and the error is shown on the channel.
  • The account owner’s existing offline email is unchanged and works alongside these channels.

FAQ

Can ScreenTinker post in Microsoft Teams when a screen goes offline?

Yes. Create a Workflows incoming webhook for the Teams channel, add a Teams alert channel in Automate → Alerts, paste the address, and press Send test.

Will I get a message every few minutes while a screen is down?

No. A channel sends one message per outage, and a back-online message only after an offline alert went out.

Does the PagerDuty incident close by itself?

Yes. The incident opens when the screen goes offline and resolves when it comes back online.

Can I send different screens to different teams?

Yes. Each channel has its own scope: all screens, some groups or some screens, and its own offline threshold.
